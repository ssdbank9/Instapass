# Instapass Guest Orders 0.2.2

Guest checkout requires no login or account. Receipts and tracking use the required billing email. An optional different activation email is stored privately on the order; blank uses billing email. Owner order details and receipt metadata show the activation destination.

The optional My Account registration uses WooCommerce's emailed password setup and disables automatic authentication on registration. Checkout remains guest-first. No automatic license provisioning is added here.

Track Order at /track-order/ accepts POSTed native numeric order number and billing email, with a nonce, throttling and no-cache/noindex headers. Matching shows the order date, limited order items, total, payment state and—when a discount was applied—the coupon code(s) and discount amount in the order currency. It never renders a private order key, transfer reference or screenshot. The customer can ask for the private order/payment link to be emailed to the saved billing address. This is protected by a three-request/hour per-order send limit. The public status lookup follows the owner's order-number-plus-email requirement; access to activation secrets remains outside that lookup.

Bundle offers are managed under Products > Promotions: TOOLKIT5 gives 5% for two or more eligible purchased units (repeated quantities count); TOOLKIT75 gives 7.5% for three or more; TOOLKIT10 gives 10% for four or more. The owner can edit or disable each separately. Both accept guests and returning customers without first-order or per-customer limits; one coupon applies per order. Bundle thresholds count all eligible purchased units, including extra quantities of the same product and duration. Selected-product scope, schedules and per-offer coupon toggles are respected. Separate tenors retain independent prices and stock. Percentage coupons work across supported currencies; fixed coupons retain the site's USD restriction. Version 0.2.0 removes the earlier First order per email checkbox and validation as explicitly requested. Historical guest-commerce first-order fixtures document the superseded policy; use bundle-offers integration/browser acceptance for current coupon rules.

Payment methods remain owner-configured in WooCommerce Settings, Payments. This plugin adds no receiving account and no paid service. The companion reviewed theme updates supply private payment-return links, clear report/verified states, currency-appropriate proof methods and the activation destination in the confirmation receipt. Reporting a payment never marks it paid.

Rollback: deactivate this plugin and restore only the backed-up theme PHP files. Restore the exact before-values for the six setup options from the protected deployment receipt if required. Keep new customer orders and activation metadata; never overwrite the live database with a prior snapshot simply to undo code. The tracking page can be kept as a draft during rollback. Recovery artifacts and fixture credentials stay outside Git.

Generic WordPress payment notices do not use WC_Email::get_headers. The plugin supplies Reply-To support@instapass.online when no Reply-To is present, preserving explicit headers. Production wc_mail inbox verification confirmed orders@ From and support@ Reply-To with passing SPF/DKIM/DMARC.

Version0.3.0 adds repeated-unit account allocation. Default enablement is only the confirmed `claude-max-gift-x5` monthly SKU; owner policies live in Products & Offers. Two or more units require one/each/custom distribution, existing/new and valid activation destinations. Positive whole unit totals must match the cart line. Signed snapshots reject stale quantity/duration/policy. Private per-item plans survive order creation; visible summary is nonpersonal; full instructions render on normal authorised WooCommerce order/admin/email views. Different-activation fallback is taken from validated checkout data because item creation precedes order metadata hooks. Alternate Store API POST is rejected for carts requiring this classic checkout UI. Quantity coupons and prices do not change. No provider account creation, password collection or renewal automation. See ops/ACCOUNT-ALLOCATION-ACCEPTANCE.md and owner guide.
