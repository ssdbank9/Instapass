## INSTAPASS-20261108-74 - Detached-container insertBefore silently removed checkout fields from live form

- Date / project: 2026-11-08; instapass-ux mu-plugin release (collapseOptional).
- Category / status: Confirmed defect in newly deployed code; found through live verification before any customer order, root-caused, fixed and regression-covered. No orders, data or settings affected; the defect was live on the checkout for under an hour.
- Evidence / impact: `collapseOptional` appended the three optional field rows into a new `details` element BEFORE inserting the `details` into the document. The anchor row's parentNode became the detached `details`, so the following `insertBefore(details, anchor)` threw `HierarchyRequestError: The new child element contains the parent`. The rows stayed stranded inside the never-inserted `details`, silently removing "Different activation email", "Phone number" and renewal consent from the live checkout form. A checkout harness initially hid the cause twice over: a script-blocking test used `**/instapass-ux.js` which failed to match the `?ver=` cache-bust query (the block silently failed, so my script still ran), and a `replace()`-based variant toggle only removed the first of two call sites.
- Cause / prevention: Always insert a new container into the document before moving children into it. Block scripts with query-string-aware patterns (`**/*name*`). When bisecting by removing code paths, replace every call site. Suspect your own new code first and prove innocence by blocking it correctly, not by trusting a failed block.
- Verification: Isolation chain — all-JS-blocked parse (fields present), correct single-script block (fields present with `**/*instapass-ux.js*`), script-variant bisect via route fulfillment exposing the exact `HierarchyRequestError`. Fix (insert empty details first, then move rows) deployed; 24/24 public/checkout checks and 21/21 live dummy-order #191 checks pass, including the three optional fields rendering inside the collapsed toggle and full checkout/order persistence. Acceptance: ops/UX-RELEASE-ACCEPTANCE-20261108.md. Auxiliary lessons: `innerText` returns CSS-`text-transform`ed text (a lowercase regex against an uppercased hint caused a false harness failure); tile price scraping must target the real price node (`ip-term-pricing`/`ipl-credit-pricing`) because `.ipl-price` also contains the savings/coupon banner; direct listeners on tiles get orphaned when the catalog JS rebuilds those nodes, so delegated document-level events are required.

## INSTAPASS-20261108-73 - Deployment script lint gate always passed

- Date / project: 2026-11-08; Terms/refund-copy and Telegram-handle theme deployment.
- Category / status: Confirmed harness defect; caught and corrected before any site impact. All deployed PHP files verified clean after correction.
- Evidence / impact: `ops/run-terms-refund-copy.ps1` ran remote lint as `php -l file | grep -q "No syntax errors" && echo LINT_OK || echo LINT_FAIL`; the quoted grep pattern was split across SSH argument layers ("grep: syntax: No such file or directory"), every file printed LINT_FAIL, and the pipeline still exited0, so the script's `$LASTEXITCODE` abort never fired and it installed the files.
